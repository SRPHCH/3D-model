# Little Explorer — มาสคอตนักสำรวจ 3D

![preview](docs/preview.jpg)

มาสคอต 3 มิติแบบตัวการ์ตูนน่ารัก: ตัวกลมป้อมแบบตัวอ้วนกลม (อิงรูปที่ 1), ผิวขาวอมชมพูและแก้มแดง (อิงรูปที่ 2),
แต่งชุดนักสำรวจ (อิงรูปที่ 3) ธีมสีขาว–ชมพูพาสเทล: เสื้อโปโลขาวลายแถบชมพูเฉียงตามแบบเสื้อทีม,
หมวกแก๊ปขาวปีกชมพูติดโลโก้ GEP, ผ้าพันคอชมพู, สายสะพายติดเข็มกลัด, กระเป๋าเสื้อพิมพ์ตราโรงเรียน, เข็มขัดขาว,
กางเกงขาสั้นชมพู, รองเท้าบูทชมพู, เป้พร้อมถุงนอน, เชือกขดที่สะโพก และถือธงสามเหลี่ยมโลโก้ GEP ที่ปลิวออกด้านนอก
พื้นหลังสีขาวพร้อมแสงและเงา

โลโก้อยู่ใน `src/assets/` (`gep-logo.webp`, `school-logo.webp`) ถ้าจะเปลี่ยนโลโก้ ให้แทนที่ไฟล์แล้วรัน `npm run build`

- **ไฟล์เดียวจบ**: `index.html` (~690 KB, gzip ~215 KB) รวม three.js ไว้ในไฟล์แล้ว ไม่ต้องโหลดจาก CDN
  เปิดจากดิสก์ได้เลย หรือวางบนเว็บเซิร์ฟเวอร์ใดก็ได้
- **โต้ตอบได้**: ลากเพื่อหมุน, เลื่อน/บีบเพื่อซูม, แตะตัวน้อง (หรือกด Space) ให้กระโดด
- **มีแอนิเมชัน**: หายใจ, โยกตัว, หันมองรอบๆ, กะพริบตา, โบกมือ และธงพลิ้ว
- โมเดลทั้งหมดสร้างด้วยโค้ด (ไม่มีไฟล์โมเดล/รูปภายนอก)

## การ optimize สำหรับเซิร์ฟเวอร์ 1 vCPU

**ฝั่งเซิร์ฟเวอร์**: การเรนเดอร์ 3D เกิดขึ้นบนเบราว์เซอร์ของผู้ชม ไม่ได้เกิดบนเซิร์ฟเวอร์
เซิร์ฟเวอร์แค่ส่งไฟล์ static หนึ่งไฟล์ เครื่อง 1 vCPU จึงรับได้สบาย ใช้ `nginx.conf.example` (gzip_static + cache)
แล้วบีบอัดไฟล์ไว้ล่วงหน้าด้วย `gzip -k -9 index.html` เพื่อไม่ให้เปลือง CPU ไปกับการบีบอัดทุก request

**ฝั่งเครื่องที่แสดงผล** (รวมถึงกรณีเปิดดูบนเครื่องที่ไม่มี GPU เช่น VPS/VM ซึ่งเบราว์เซอร์ต้องเรนเดอร์ด้วย CPU):

| ระดับ | ใช้เมื่อ | การตั้งค่า |
|---|---|---|
| สูง | PC/โน้ตบุ๊กที่มี GPU | PBR + clearcoat/sheen, เงา 2048, สูงสุด 60 fps, ความละเอียดสูงสุด 2x |
| กลาง | มือถือ / เครื่อง ≤4 คอร์ | PBR มาตรฐาน, เงา 1024 อัปเดตเว้นเฟรม, สูงสุด 60 fps |
| ประหยัด | ไม่มี GPU (SwiftShader/llvmpipe) หรือ ≤2 คอร์ | แสงแบบ matcap (อ่าน texture ครั้งเดียวต่อพิกเซล), ไม่มี shadow map (ใช้เงาสัมผัสแทน), โพลิกอนน้อยลง, สูงสุด 30 fps |

ระบบเลือกระดับให้อัตโนมัติ หรือเลือกเองได้จากปุ่มมุมขวาบน / ใส่ `?q=high|medium|low` ต่อท้าย URL

เทคนิคที่ใช้เพิ่มเติม:
- **รวมชิ้นส่วนที่ไม่ขยับ** ให้เหลือ 1 mesh ต่อวัสดุ และระดับประหยัดยังฝังสีลง vertex จนทั้งตัวเหลือ **16 draw calls** (จากราว 65)
- **ความละเอียดปรับเอง**: ถ้าเฟรมช้าจะลดความละเอียดลง แต่ถ้าลดแล้ว fps ไม่ดีขึ้น
  (ซึ่งเกิดบ่อยตอนเรนเดอร์ด้วย CPU) จะคืนความละเอียดเดิมเพื่อไม่ให้ภาพเบลอโดยเปล่าประโยชน์ จากนั้นจึงปิดเงาเป็นขั้นต่อไป
- **โหมดประหยัดตอนว่าง**: ไม่มีการโต้ตอบเกิน 20 วินาทีจะลด fps ลงครึ่งหนึ่ง และหยุดเรนเดอร์ทันทีเมื่อสลับแท็บ
- สร้างผิวเฉพาะส่วนที่มองเห็น (ใต้เสื้อและหมวกไม่มีผิว) เพื่อลด overdraw และใช้ canvas ทึบ (`alpha: false`)

ผลทดสอบ (Chromium headless ใช้ SwiftShader คือเรนเดอร์ด้วย CPU ล้วน):
- ล็อกไว้ **1 คอร์** ที่หน้าจอ 1280×720: ประมาณ 10–14 fps (สภาพแย่ที่สุด เพราะเบราว์เซอร์ทั้งหมดและ GPU จำลองแชร์คอร์เดียวกัน)
- 2 คอร์: ประมาณ 17 fps / 4 คอร์: 30 fps (เต็มเพดานของระดับประหยัด)
- เครื่องที่มี GPU ใดๆ (มือถือหรือ PC ทั่วไป) วิ่งได้ 60 fps เต็ม

แอนิเมชันคำนวณตามเวลาจริง ถ้า fps ต่ำลง ตัวละครก็ยังขยับด้วยความเร็วปกติ ไม่หน่วงหรือสโลว์

กด `F` หรือใส่ `?fps` เพื่อแสดง fps และความละเอียดที่ใช้อยู่

## Deploy

- **Render (Static Site, แนะนำ)**: New → Static Site → เลือก repo นี้ → Build command: `echo ok` → Publish directory: `.`
  (หรือใช้ `render.yaml` ผ่าน Blueprint) ไม่มีเซิร์ฟเวอร์ให้รัน จึงไม่กิน CPU เลย
- **Render Web Service / Railway / VPS**: `npm start` รัน `server.mjs` (ไม่มี dependency) เสิร์ฟ `index.html` แบบ gzip
  ใช้พอร์ตจากตัวแปร `PORT` และมี health check ที่ `/healthz`

## พัฒนาต่อ

```bash
npm install
npm run build   # bundle src/main.js + three.js → index.html (ไฟล์เดียว)
npm run serve   # เปิดดูที่ http://localhost:8080
```

- `src/main.js` — โมเดล, วัสดุ, แสง, แอนิเมชัน และระบบปรับคุณภาพ
- `src/template.html` — หน้า HTML/CSS (UI)
- `build.mjs` — esbuild bundle แล้วฝังลงใน `index.html`
